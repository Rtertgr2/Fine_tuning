# ระยะที่ 2: ไปป์ไลน์สร้างข้อมูล

**ประมาณการ:** ประมาณ 12-13 วันทำงาน **ต้องทำก่อน:** ระยะ 1 (มีสคีมา validator และ gold set) **ส่งผลให้:** ระยะ 3 มีข้อมูลพอเทรน

## 1. เป้าหมาย

สร้างตัวอย่างจำนวนมากอย่างมีคุณภาพ โดยให้ **ความถูกต้องมาจากการรันจริงและข้อมูลอ้างอิงที่รู้คำตอบ** ไม่ใช่จากความเชื่อของโมเดลครู แล้วส่งเข้าคิวรีวิวก่อนเข้าชุดข้อมูล

## 2. ขอบเขต

**ทำ**
- ตัวสร้างข้อมูลครบ 4 หมวดด้วยโมเดลครู
- Sandbox ที่รัน tool จริงของ agent
- ตัวยืนยันผลอัตโนมัติ
- คิวรีวิวคนและตัวกรองความลับ/ซ้ำ/ปนกับชุดทดสอบ

**ไม่ทำ**
- การสร้างข้อมูลจาก log จริง (ระยะ 6)

## 3. ข้อกำหนดเบื้องต้น

- ระยะ 1 เสร็จ (validator, gold set, API นำเข้า)
- เข้าถึงโมเดลครูที่แข็งแรงกว่า 7B ได้ (API หรือรันเอง)
- **ตรวจข้อกำหนดการใช้งานของโมเดลครูก่อน** ว่าอนุญาตให้นำ output ไปเทรนโมเดลอื่นหรือไม่
- Docker ใช้งานได้บนเครื่องที่จะรัน sandbox
- กำหนดงบประมาณสูงสุดของค่าเรียกโมเดลครู

## 5. ส่วนประกอบ

### 5.1 Sandbox executor

- คอนเทนเนอร์ Docker ต่อหนึ่งงาน: ไม่มีเครือข่าย, ผู้ใช้ไม่ใช่ root, จำกัด CPU/RAM/เวลา, workspace แบบ tmpfs
- ตัวจริงของ tool 3 ตัวที่ป้องกัน path traversal (ห้ามออกนอก workspace)
  - `git_checkout(branch)`
  - `read_file(path)`
  - `write_file(path, content)` รับเนื้อหาไฟล์เต็มเท่านั้น
- ชุดนโยบายที่บล็อกได้ เช่น ไฟล์ .env, ไฟล์นอก workspace, ไฟล์ขนาดเกินกำหนด และตอบกลับเป็นข้อความ "Blocked by policy: ..." ในรูปแบบคงที่
- บันทึกทุกการเรียกเป็น trajectory (ข้อความ, tool call, ผลลัพธ์, เวลา)

### 5.2 Task seeds

- repo เล็กๆ (Python, JavaScript) พร้อมโจทย์และชุดทดสอบ ที่ **ทดสอบล้มเหลวก่อนแก้และผ่านหลังแก้**
- แหล่งที่มา: repo ที่ใบอนุญาตอนุญาตให้ใช้ (ตรวจใบอนุญาตทุกแหล่ง) และ repo สังเคราะห์ที่โมเดลครูสร้างแล้วผ่านการยืนยันด้วยการรันเทสต์
- บันทึก `group_id` ต่อ repo เพื่อกันรั่วตอนแบ่งข้อมูล
- ความหลากหลาย: ภาษา, ขนาดไฟล์, ประเภทงาน (แก้บั๊ก, เพิ่มฟีเจอร์, รีแฟกเตอร์)

### 5.3 สูตรสร้างแต่ละหมวด

**หมวด tool (Multi-turn)**
1. ให้ครูแก้โจทย์ผ่าน tool จริงใน sandbox
2. เก็บเฉพาะ trajectory ที่ทดสอบผ่านและมี tool_call 3-6 รอบ
3. ตรวจด้วย validator ของระยะ 1 (โดยเฉพาะ write_file ต้องเป็นไฟล์เต็ม)

**หมวด loop (Anti-Loop และ Self-Correction)**
1. นำ trajectory ที่สำเร็จ แล้ว **ฉีดความผิดพลาดตามที่กำหนด** ณ ขั้นที่ k
2. ให้ครูสร้างการรับมือที่ถูกต้อง แล้วรันต่อใน sandbox ให้ยืนยันผล
3. เก็บเฉพาะที่จบสำเร็จ หรือจบด้วยรายงานว่าทำไม่ได้พร้อมเหตุผลที่ตรวจได้

| ประเภทความผิดพลาดที่ฉีด | ตัวอย่างการรับมือที่ถูก |
|---|---|
| File not found (path ผิด) | read_file ตรวจโครงสร้าง หรือแก้ path |
| Syntax error หลัง write_file | read_file ตรวจไฟล์จริง แล้วเขียนไฟล์เต็มที่แก้แล้ว |
| Blocked by policy | เปลี่ยนไปเขียนไฟล์ที่อนุญาต หรือหยุดและรายงาน |
| Branch ไม่มีอยู่ | สร้างหรือเลือก branch ที่ถูก |
| ผิดซ้ำเกินกำหนดรอบ | หยุดและรายงานว่าทำไม่ได้ |

**หมวด plan (วิเคราะห์แผนและ JSON)**
1. ให้ครูเขียนแผน Markdown แล้ว **ฉีดข้อบกพร่องที่รู้แน่ชัด** (ขาด rollback, เวอร์ชันผิด, ขั้นตอนกำกวม)
2. เฉลย critique มาจากรายการข้อบกพร่องที่ฉีด ไม่ใช่จากการเดาของครู
3. ผสมแผนที่ไม่มีข้อบกพร่องเพื่อให้ได้ status ผ่านด้วย

**หมวด sec (รีวิวความปลอดภัย)**
1. **diff ที่มีช่องโหว่:** นำ commit ที่แก้ช่องโหว่จากชุดข้อมูลอ้างอิงแบบเปิด (เช่น CVEfixes ซึ่งต้องตรวจใบอนุญาต) มา **ย้อนกลับ (reverse patch)** จะได้ diff ที่เพิ่มโค้ดที่มีช่องโหว่ พร้อมป้ายกำกับจริงจาก CWE และบรรทัดที่เปลี่ยน
2. **diff สะอาด:** ใช้ commit แก้ไขปกติ และ commit ที่แก้ช่องโหว่ในทิศทางปกติ ให้ราว 50% ของหมวด
3. เสริมด้วยช่องโหว่สังเคราะห์ที่ครูเขียนตามประเภทที่กำหนด แล้วให้ Semgrep/Bandit ยืนยัน และคนตรวจซ้ำ
4. ตรวจให้แน่ใจว่า line ที่ระบุตรงกับ diff จริง (กฎ S4)

### 5.4 ตัวยืนยันและตัวกรอง

- ตัวยืนยัน: รันเทสต์ของ seed, validator ระยะ 1, ตรวจ JSON schema
- สแกนความลับ (เช่น gitleaks หรือ detect-secrets) ทุกตัวอย่าง
- ตรวจซ้ำ (hash และ near-duplicate) กับชุดข้อมูลเดิม
- **ตรวจการปนกับชุดทดสอบ:** เทียบ n-gram overlap กับ test set ของระยะ 4 ตัวอย่างที่ซ้ำเกินเกณฑ์ต้องทิ้ง
- ตรวจการกระจายตัว: สัดส่วนต่อภาษา, ต่อประเภทงาน, ต่อประเภทช่องโหว่ เพื่อไม่ให้เอียง

### 5.5 คิวรีวิว

| หมวด | นโยบายรีวิว |
|---|---|
| sec | รีวิวคน 100% เพราะป้ายผิดทำให้โมเดลเรียนผิด |
| plan | สุ่มรีวิว 30% |
| loop | สุ่มรีวิว 30% |
| tool | สุ่มรีวิว 15% เพราะมีการยืนยันด้วยเทสต์แล้ว |

การกระทำ: อนุมัติ, แก้ในตัวแก้ไขของระยะ 1, ทิ้ง พร้อมบันทึกเหตุผลของการทิ้งเพื่อปรับตัวสร้างข้อมูล

## 7. การทดสอบ

- Sandbox: ทดสอบว่าเข้าถึงไฟล์นอก workspace ไม่ได้ และไม่มีเครือข่าย
- ตัวฉีดความผิดพลาด: ผลลัพธ์ tool ตรงรูปแบบคงที่ทุกครั้ง
- เทียบตัวอย่างสุ่ม 30 ตัวอย่างต่อหมวดกับ gold set ด้านคุณภาพ
- ทดสอบตัวตรวจ contamination ด้วยตัวอย่างที่ตั้งใจให้ซ้ำ
