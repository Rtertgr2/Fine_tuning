# Fine-tuning Workbench: แผนหลัก

เอกสารนี้เป็นสารบัญและข้อตกลงร่วมของทุกระยะ รายละเอียดของแต่ละระยะอยู่ในไฟล์แยก 01 ถึง 06

## เป้าหมาย

ทำให้วงจร **เตรียมข้อมูล → เทรน → ประเมิน → deploy → เก็บเคสผิดพลาด** ทำซ้ำได้ วัดผลได้ และย้อนกลับได้ โดยเป้าหมายสุดท้ายคือโมเดล 8B (NousResearch/Hermes-2-Pro-Llama-3-8B) ที่ทำงานเป็น agent 3 สถานะ (Plan → Code → Review) ได้เสถียรบนเครื่อง VRAM 12 GB (ดู D1 ใน docs/decisions.md สำหรับเหตุผลที่เลือก 8B แทน 7B)

        |                                        |
        v                                        v
[3 Training Launcher] -> [5 Deploy] -> (ใช้งานจริง) -> [6 Active Learning]

## Milestones

| รหัส | เมื่อไร | เงื่อนไขผ่าน |
|---|---|---|
| M0 | จบสัปดาห์ 2 | ส่งออกชุดข้อมูล 100 ตัวอย่างที่ผ่านการตรวจทั้งหมด |
| M1 | กลางสัปดาห์ 5 (G1) | ได้คะแนน baseline ของ base model ครบทุกด่านและเลือก base model |

ระหว่างทางมี G2 (สิ้นสัปดาห์ 7) เป็นจุดตัดสินใจว่ารอบเทรนนำร่องคุ้มพอจะขยายข้อมูลหรือไม่ โมเดลนำร่องไม่ต้องผ่าน gate เต็ม

## ข้อตกลงร่วมของทุกระยะ

1. **Chat template ล็อกตัวเดียว** ใช้ `apply_chat_template` ของโมเดลตอนเทรน และรัน llama-server ด้วย `--jinja` ที่ template เดียวกัน มีการทดสอบเทียบผลก่อน deploy ทุกครั้ง
2. **ทุกอย่างมีเวอร์ชันและ hash** ชุดข้อมูล, config เทรน, โมเดล, ชุดทดสอบ ผูกกันด้วย manifest.json เพื่อย้อนรอยได้
3. **แยก test set ออกจาก train ตั้งแต่ต้น** ห้ามแก้หลังสร้าง และมีการตรวจการซ้ำซ้อนอัตโนมัติทุกครั้งที่สร้างชุดข้อมูลใหม่
4. **Seed คงที่** ทุกงานที่มีการสุ่ม (แบ่งข้อมูล, เทรน, eval) บันทึก seed ลงรายงาน
5. **ไม่มีความลับในข้อมูล** ผ่านตัวสแกนความลับก่อนเข้าฐานข้อมูลเสมอ
6. **ตัวตรวจข้อมูลชุดเดียว** ใช้โค้ด validator ตัวเดียวกันทั้งตอนสร้างข้อมูลและตอน eval

## Definition of Done ทั่วไป (ใช้กับทุกระยะ)

- มี unit test ของส่วนที่เป็นตรรกะหลัก และผ่านทั้งหมด
- รันซ้ำด้วย config เดิมแล้วได้ผลเหมือนเดิม
- มีเอกสารสั้นๆ ว่ารันอย่างไร ผลลัพธ์อยู่ที่ไหน
- ผลลัพธ์ทุกอย่างมี manifest ผูกกับเวอร์ชันข้อมูลและโค้ดที่ใช้
