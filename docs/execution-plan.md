**ผู้ทำ:** คนเดียว, เต็มเวลา (~40 ชม./สัปดาห์)

## จุดตัดสินใจ Go/No-go

### G0 (สิ้น W0): พร้อมเริ่มไหม
- [ ] base model โหลดบน llama-server ได้, วัด tokens/s ที่ 8k และ 32k
- [ ] แท็ก `<tool_call>` เรนเดอร์ตรงกับ chat template (D2)
- [ ] ตรวจข้อกำหนดโมเดลครูแล้ว (D8)
- [ ] dry run 10 steps รอดที่ 8k

### G1 (สิ้น W5): ควร fine-tune ไหม
| ผล baseline | การตัดสินใจ |
|---|---|
| ด่าน 1-3 ผ่านเกณฑ์ทุกด่าน | **ไม่ fine-tune** ใช้ base + circuit breaker |
| ด่าน 1 ต่ำ | ลอง grammar ก่อน ถ้ายังไม่ถึงค่อยเทรน |
| ด่าน 2 ต่ำ | เป้าหมายหลักของการเทรน |
| ด่าน 3 ต่ำ/FP สูง | เป้าหมายของการเทรน + Semgrep เป็นชั้นที่สอง |

### G2 (สิ้น W7): รอบนำร่องคุ้มไหม
- [ ] ด่านเป้าหมายดีขึ้นอย่างมีนัยสำคัญ (CI 95% ไม่ทับ base หรือดีขึ้น ≥10 จุด)
- [ ] Regression ลดไม่เกิน 3 จุด
- [ ] ผ่าน template parity และรับได้ตามเป้าความเร็ว

### G3 (สิ้น W10): ขึ้น production ได้ไหม
ผ่านทุกด่านตามแผน 04 §8 บน quantization ที่ใช้จริง

### G4 (สิ้น W12): วงจรเรียนรู้ต่อเนื่องใช้ได้ไหม
เคสผิดพลาด 1 เคส → ข้อมูลเทรน → เทรนซ้ำ → ผ่าน regression

## การติดตามและการปรับ

**ทบทวนทุกสัปดาห์ (30 นาที):**
- งานที่เสร็จ vs ตาราง
- วันที่ใช้จริง vs ประมาณการ
- ความเสี่งที่เปลี่ยน

**กฎปรับ:** ถ้า W2 เกินประมาณการ >30% คูณประมาณการที่เหลือด้วยอัตราเดียวกัน

**ลำดับตัดขอบเขต (ตัดจากบนลงล่าง):**
1. UI v2 (React) ทั้งชุด — คง UI v1
2. แดชบอร์ดขั้นสูง + Runner โหมด B — คงโหมด A
3. ระยะ 6 ให้เหลือแบบกึ่งมือ
4. ลดเป้าข้อมูลรอบสอง (1,000-1,500)
5. **ห้ามตัด:** ชุดทดสอบ frozen, loss mask check, template parity, gate, rollback

## ทะเบียนความเสี่ยง

| ความเสี่ยง | สัญญาณ | วิธีรับมือ |
|---|---|---|
| ขอบเขตบานปลาย | งานนอกตาราง >20% | ตัดตามลำดับด้านบน |
| Base ผ่านเกณฑ์อยู่แล้ว | ผล G1 | ไม่ fine-tune |
| รอบนำร่องไม่ดีขึ้น | ผล G2 | วินิจฉัย template → ข้อมูล → hyperparameter |
| Template ไม่ตรง | tool call พังตอนใช้ | parity test บังคับ W6 |
| VRAM ไม่พอ | ผล W0 + ด่าน 4 | ลด quantize/context/KV cache |
| ข้อมูลแคบ | รายงานกระจายเอียง | เพิ่ม seeds + ผสมข้อมูลจริง |
| ปัญหาใบอนุญาต | ผล G0 | เขียนมือมากขึ้น |
| ประมาณการผิดมาก | ช้า >30% ใน W2 | คำนวณใหม่ + ตัด |
| Test set รั่ว | overlap เตือน | ทิ้ง + สร้าง v002 |

## นิยามความสำเร็จ

- โมเดล production ผ่านทุกด่านบน quantization ที่ใช้จริง
- ดีกว่า base ในด่านเป้าหมาย โดยไม่ regression เกินเกณฑ์
- วงจร ข้อมูล → เทรน → ประเมิน → deploy → rollback ซ้ำได้จาก UI
- เคสผิดพลาดวนกลับเป็นข้อมูลรอบถัดไปได้
